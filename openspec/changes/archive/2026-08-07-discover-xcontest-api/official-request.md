# XContest official request draft

To: support@xcontest.org, xctrack@xcontest.org, info@xcontest.org

Subject: Request for documented XContest upload and flight catalogue interface

Hello XContest team,

We are evaluating a future BrandyFly integration and need written clarification
before we build anything user-facing.

Please confirm whether XContest permits:

- Direct flight upload from a third-party mobile client
- Automated flight catalogue retrieval for route-planning or synchronisation

If either capability is permitted, please share the documented interface and
contract details, including:

- Authentication and credential lifecycle
- Required request and response fields
- Success, duplicate, retryable failure, and permanent failure semantics
- Pagination, filtering, and incremental sync rules
- Rate limits, caching, retention, attribution, and redistribution terms
- Any restrictions on test credentials, synthetic flights, or public visibility
- Whether the planned 08:00 `Europe/Vienna` catalogue schedule is allowed

Thank you.
